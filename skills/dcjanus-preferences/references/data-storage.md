# 数据存储、分析与归档偏好

- 单机 OLAP：默认优先使用 DuckDB，适用于本地分析查询、列式扫描、聚合、时间序列统计以及分析型缓存。
- 单机 OLTP：默认优先使用 SQLite，适用于点查询、频繁小事务、状态管理、元数据与交互式应用持久化。
- 结构化数据归档：默认优先使用 Parquet，适用于长期保存、分区数据集、批量交换与后续分析；不将 Parquet 当作需要频繁行级更新的事务存储。
- DuckDB 与 Parquet 场景需要选择压缩算法时，默认使用 zstd 及其默认压缩级别，不手动固定 level。只有存在明确的兼容性、CPU/延迟、存储成本或外部格式要求时，才改用其它算法或压缩级别。
- 混合负载按主要访问模式选型：以扫描、聚合和批处理为主时倾向 DuckDB，以并发小事务和点更新为主时倾向 SQLite；两类需求都很重时，先说明取舍，必要时分离事务存储与分析存储。
