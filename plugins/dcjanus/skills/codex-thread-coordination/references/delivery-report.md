# 交付报告

按约定方式交付变更与报告，不要求先推送或创建 PR/MR。需要平台发布时，在相应权限范围内推送、创建并回读实际 URL、head 和状态；GitHub PR 调用 `attach_artifact`，其它工件仅用工具支持的类型。按下列信息交付；失败或未授权项不能写成完成。

```markdown
结果：完成/阻塞及可观察行为
交付身份：方式 / 仓库与 worktree / branch/ref / 来源提交范围
最终 head：完整 SHA；未提交时明确 diff 与工作区状态，不虚构 SHA
依赖：直接父 SHA / 可消费条件与缺口 / 未合入或已合入状态
PR/MR（如已发布）：URL / 当前状态；GitHub PR 补 attach 结果
基线与环境：必要的 base SHA、工具链或验证环境
验证：测试覆盖的行为、结果及对应 SHA
组合状态：未集成 / 集成 ref 与 SHA / 来源映射 / 组合验证结果；正式合入另列实际结果
未验证事项：缺口、原因、CI 排队/失败等当前状态
工作树：绝对路径 / branch / clean 或已有改动归属
资源恢复：释放/恢复结果、仍占用资源及归属
阻塞与下一步：具体条件与负责人
通知：目标真实 threadId / host / 授权来源 / 成功或未完成及原因
```

通知时发送清晰、完整的自然语言报告，沿用目标会话的模型设置，除非人类明确要求改变。复用仍适用的直接人类消息授权，不重复询问；派工时发现缺失就尽早澄清双向通知需求，交付时仍缺失则说明未授权并保留独立交付。工具失败时记录返回错误，停止自动重试、不猜目标 ID。将报告保留在自己的 final，供主会话通过 `wait_threads` 获取，但不能声称主动通知成功。

主会话收到报告后核实当前交付 ref/head、实际 diff 及适用的平台状态。若测试绑定 H1，而交付已变成 H2，按变更影响重新验证；父提交、base 或环境变化也作相同判断。报告中的 queued CI、idle 状态和“代码完成”均不证明已验收或可正式合入。
