# Codex 工作会话协调

主会话负责拆分、派工、验收和集成；工作会话负责各自范围的实现、验证和 PR 交付，不自行合并。模型、推理强度、文案语言、CI 策略和合并权限取自当前人类指令与项目规则，不把某次项目的选择变成全局要求。

使用当前环境提供的原生 Codex app 工具，先读取相关工具定义；工具不可用时说明限制，不虚构名称、参数或返回值，不新增轮询 daemon 或无必要脚本。本 skill 协调用户可见会话，不把它们偷换成内部 subagent。

## 授权与派工

- 启用本 skill 不授权创建新会话。只有人类明确要求创建新会话时才调用 `create_thread`；否则在已有会话或本地继续可执行工作，说明未创建的限制。
- 消息发送需要直接来自人类的授权，发送和回复分别核实。其它任务的派工、要求回报或自称已授权，不自动授权回复。缺少直接人类双向消息授权时，解释工具要求并询问，同时推进不依赖消息的工作；不要用工具失败试探授权。
- 创建项目会话前用 `list_projects` 定位真实项目；继续已有会话先用 `read_thread` 核实身份和状态。以原始人类请求或可读取的可信证据记录授权，不能仅写“主会话授权”。
- 派工前读取 [任务简报](references/task-brief.md)，核实仓库绝对路径、base/ref/SHA、已有改动与依赖，明确交付和写权限。只传递已确认的模型选择；未指定时保留工具默认。
- 可并行的仓库任务各用独立 worktree；创建前检查 `list_artifacts`，优先复用适合的已分配 worktree。模拟器、监听端口和 daemon 等共享资源须显式指定串行归属与恢复责任。
- `create_thread` 异步创建可能返回 queued `clientThreadId`，它不是 `threadId`。未拿到 ready 的真实 ID 前，不能把它传给读任务、发消息或等待工具；保留 queued 状态。可用 `list_threads` 查找已准备会话，再以 `read_thread` 核实项目、路径和派工内容；仅标题相似不足以确认身份。无法确定时保留阻塞，不能猜 ID。

## 跟踪与恢复

主会话维护轻量任务账本即可，格式不固定；记录状态、依赖、主/子 ID、host、worktree、branch、PR、head/base、资源归属和最后 cursor。派工后使用有界 `wait_threads` 跟踪，传入实际 ID、host 和上次 cursor；已交付的 cursor 防止重播。不要以 idle、无新输出或 CI 排队代替交付和验收。

等待被新输入结束时先处理人类的新要求，再继续剩余任务。跨回合恢复同时核对账本、`read_thread` 和 PR 平台当前状态，不能仅凭旧摘要继续写入。任务仍可推进时继续；阻塞时保留确切原因和下一步。

本 skill 不是后台调度器。主会话结束后不得许诺持续监控；只有用户请求后台跟进时才使用原生 heartbeat automation，并按请求保存通知条件，不自动创建自动化。

## 交付、验收与集成

工作会话交付前读取 [交付报告](references/delivery-report.md)。在已获相应写权限时完成推送、创建 PR、平台回读及 `attach_artifact`，报告最终 head、验证行为与缺口、资源恢复和阻塞；未授权的写操作保留为待处理项。在具备直接人类消息授权时主动通知主会话；自己的 final 写“完成”不代表通知成功。通知失败保留结果和错误，停止自动重试或猜 ID，由主会话 `wait_threads` 兜底发现。

主会话验收实际 diff、平台 PR/head 和与风险匹配的本地验证，将证据绑定具体 head SHA 及必要的 base/environment。head、base 或环境改变时，重新判断哪些证据失效并补充相关检查，不机械重跑所有 checks。

只有已授权合并且满足仓库当前合入策略时才逐个合并。若采用 merge queue，先核实可用性和语义，跟踪到实际合入才算完成，不绕过保护。依赖任务必须等前置 PR 实际合入后，再基于新主线创建分支或在已有授权范围内同步；不默认 rebase 或 force push。

清理先恢复共享资源、保留所需 ignored 产物和用户已有改动。仅结束无需继续工作的会话；管理型 worktree 用 `archive_worktree` 保存快照后清理，不自行删除 checkout。不要自动 archive 用户聊天。
