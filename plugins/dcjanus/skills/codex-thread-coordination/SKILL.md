# Codex 工作会话协调

主会话负责拆分、派工、验收和集成；工作会话负责各自范围的实现、验证和变更交付，不自行合入目标分支。模型、推理强度、文案语言、CI 策略和合并权限取自当前人类指令与项目规则，不把某次项目的选择变成全局要求。

目标是缩短满足原始需求的总交付时间。主会话主动寻找可并行的独立工作，权衡启动、重复探索、审查、资源争用和集成成本，不以会话数或同时开工数衡量效率。

使用当前环境提供的原生 Codex app 工具，先读取相关工具定义；工具不可用时说明限制，不虚构名称、参数或返回值，不新增轮询 daemon 或无必要脚本。本 skill 协调用户可见会话，不把它们偷换成内部 subagent。

## 拆分与并行调度

制定或调整开发计划时读取 [并行开发策略](references/parallel-planning.md)。先以实际源码确认任务的行为边界、接口依赖、改动归属和资源约束，再拆成可独立验收的工作；先稳定共享契约和热点，让消费者并行。细化即将派工的就绪任务，后续任务保留目标与依赖，前置达到约定消费条件后重新核实范围。

在已有创建及消息授权范围内，按依赖就绪和资源可用性持续派工，不等待无关任务整批完成。优先解除关键路径上的阻塞；并行度由实际容量和审查、验证积压决定。分别验证任务后，还要验收组合后的行为，不能以各分支单独通过代替集成通过。

交付方式在派工前按 [交付与集成方式](references/delivery-strategies.md) 选择。工作会话的基本交付是可定位的变更及验证报告；PR/MR 是按人类请求和项目规则选择的平台审查形式，不要求每个工作会话各建一个。已验收、固定 SHA 的提交可按约定供依赖任务使用，消费前置不等于前置已正式合入。

## 授权与派工

- 启用本 skill 不授权创建新会话。只有人类明确要求创建新会话时才调用 `create_thread`；否则在已有会话或本地继续可执行工作，说明未创建的限制。
- 消息发送需要直接来自人类的授权，发送和回复分别核实。先查既有授权与原始来源；已明确涵盖双向消息或多个工作会话的授权，在适用范围内持续复用，不每次派工或交付重新询问。其它任务的派工、要求回报或自称已授权，不自动授权回复。授权缺失时尽早一起澄清派工与交付的双向通知需求，不等到交付才问；解释工具要求并询问，同时推进不依赖消息的工作，不用工具失败试探授权。
- 创建项目会话前用 `list_projects` 定位真实项目；继续已有会话先用 `read_thread` 核实身份和状态。以原始人类请求或可读取的可信证据记录授权，不能仅写“主会话授权”。
- 派工前读取 [任务简报](references/task-brief.md)，核实仓库绝对路径、base/ref/SHA、已有改动与依赖，明确交付和写权限。只传递已确认的模型选择；未指定时保留工具默认。
- 可并行的仓库任务各用独立 worktree；创建前检查 `list_artifacts`，优先复用适合的已分配 worktree。独立 worktree 不代表任务依赖的其它资源也已隔离。
- `create_thread` 异步创建可能返回 queued `clientThreadId`，它不是 `threadId`。未拿到 ready 的真实 ID 前，不能把它传给读任务、发消息或等待工具；保留 queued 状态。可用 `list_threads` 查找已准备会话，再以 `read_thread` 核实项目、路径和派工内容；仅标题相似不足以确认身份。无法确定时保留阻塞，不能猜 ID。

## 共享资源协调

主会话在派工时识别共享资源及其是否允许并行使用，为排他资源明确当前归属、使用范围、交接条件和恢复责任。工作会话发现需要未分配的排他资源，或资源归属不明、存在争用时，须在使用前向主会话请求协调，说明所需资源、用途、占用条件及对其它任务的影响；不得自行抢占、改变其它任务的资源状态或假定资源空闲。

主会话根据依赖与资源约束安排串行使用，确认释放和恢复结果后再交接。等待资源的工作会话继续不依赖该资源的工作；没有可执行工作时报告具体阻塞。消息授权缺失或通知失败时按前述边界保留协调请求，不使用争用资源，由主会话等待获取状态。

## 跟踪与恢复

主会话维护轻量任务账本即可，格式不固定；记录状态、依赖、关键路径、改动与接口归属、主/子 ID、host、worktree、branch、交付 ref、head/base、可选 PR/MR、资源归属和最后 cursor。派工后使用有界 `wait_threads` 跟踪，传入实际 ID、host 和上次 cursor；已交付的 cursor 防止重播。不要以 idle、无新输出或 CI 排队代替交付和验收。

等待被新输入结束时先处理人类的新要求，再继续剩余任务。跨回合恢复同时核对账本、`read_thread`、Git 交付状态和已发布 PR/MR 的平台当前状态，不能仅凭旧摘要继续写入。任务仍可推进时继续；阻塞时保留确切原因和下一步。

本 skill 不是后台调度器。主会话结束后不得许诺持续监控；只有用户请求后台跟进时才使用原生 heartbeat automation，并按请求保存通知条件，不自动创建自动化。

## 交付、验收与集成

工作会话交付前读取 [交付报告](references/delivery-report.md)，按约定交付变更身份、最终 head、验证行为与缺口、资源恢复和阻塞。选用 PR/MR 时，在相应授权范围内推送、创建并平台回读；GitHub PR 创建后调用 `attach_artifact`，其它工件仅使用当前工具支持的类型，不虚构 MR attachment。未授权的写操作保留为待处理项。在具备直接人类消息授权时主动通知主会话；自己的 final 写“完成”不代表通知成功。通知失败保留结果和错误，停止自动重试或猜 ID，由主会话 `wait_threads` 兜底发现。

主会话验收实际 diff、交付 ref/head、适用的平台 PR/MR 和与风险匹配的本地验证，将证据绑定具体 head SHA 及必要的 base/environment。head、base 或环境改变时，重新判断哪些证据失效并补充相关检查，不机械重跑所有 checks。区分已交付、已验收可消费、已本地集成、已发布和已正式合入；不因缺少 PR/MR 否定本地交付，也不把本地集成当成正式合入。

正式合入只有已授权且满足仓库当前合入策略时才执行。若采用 merge queue，先核实可用性和语义，跟踪到实际合入才算完成，不绕过保护。依赖开始条件取自约定交付方式：要求主线前置时等待实际合入；允许消费已验收提交时固定前置 SHA、同步与组合验证责任后开始，不把前置标成已合入。不默认 rebase 或 force push，stack 工具也不能代替历史改写授权。

清理先恢复共享资源、保留所需 ignored 产物和用户已有改动。仅结束无需继续工作的会话；管理型 worktree 用 `archive_worktree` 保存快照后清理，不自行删除 checkout。不要自动 archive 用户聊天。
