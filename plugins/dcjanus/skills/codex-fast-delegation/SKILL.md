# 快速子代理委派

用于缓解特定主模型响应较慢的临时策略。主模型速度改善后，从脚本白名单移除对应模型，或停用整个 skill。

## 先检查当前模型

从本 skill 目录执行 `./scripts/check_current_model.py --help` 了解入口，再执行脚本；需要结构化输出时使用 `--json`。

脚本读取 `CODEX_THREAD_ID`，通过只读 Codex `thread/read` 获取 rollout 路径，读取最后一条完整 `turn_context.model`。`CODEX_BIN` 可指定 Codex 可执行文件；未设置时使用 PATH 中的 `codex`，沿用进程的 Codex 配置环境。

仅当脚本返回 `recommended: true` 时采用下列策略。白名单在脚本中硬编码并精确匹配，初始仅含 `gpt-6.1-sol`；未命中或无法确认模型时，保持使用本 skill 前的工作方式，不猜测模型、不扩大匹配范围。主模型切换后重新检查。命中名单只是允许考虑委派，仍需判断任务是否适合。

## 委派策略

- 对需求明确、边界清晰、预计短周期完成、实现风险低且结果容易验证的任务，优先考虑快速 subagent，例如按既定方案做局部修改、机械性批量调整、定向检索与信息提取。任务只需一两步，或启动、交接与验收开销预计超过收益时，由主 agent 直接完成。
- 支持指定模型与推理强度时，显式使用 `gpt-6-luna` + `high`，避免继承主模型；只传精简但充分的上下文，明确目标、修改范围、约束、验收标准与返回内容。独立且无文件写入冲突的任务才并行委派。
- 主 agent 保留需求判断、必要的方案设计、结果审查与最终验证责任，避免重复执行已验收的工作。需求含糊、跨模块耦合明显、需要复杂推理或涉及高风险变更时，沿用原工作方式，由主 agent 或适合的更强模型处理。
- 快速 subagent 遇到超出既定范围的歧义、验证失败或反复尝试无进展时，由主 agent 接管或升级模型。

## 回退

达到 subagent 数量上限、无法创建子代理或指定快速模型不可用时，暂时回退到使用本 skill 前的工作方式，由主 agent 继续当前任务。不要等待空位、反复重试、终止其他 agent 腾出名额，或换用其它进程绕过上限。已经运行的子代理按原任务正常收尾，主 agent 接手尚未开始的工作，避免重复修改。

此策略只调整执行方式，不扩大用户对提交、推送或外部操作的授权。
