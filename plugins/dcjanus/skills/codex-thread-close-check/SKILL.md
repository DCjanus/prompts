# Codex Thread Close Check

检查当前 thread 是否已经完成约定事项，为用户决定是否关闭提供依据。只做检查和报告，不执行关闭、归档、删除或顺手补做遗留事项。

## 检查

- 回顾当前 thread 的原始目标、后续追加要求、Agent 承诺和已有结果，不只看最后一轮或任务列表的完成标记。
- 逐项核对是否还有未完成的交付、未回答的问题、待验证的结果、等待中的审批或外部任务，以及仍需关注的后台命令或子任务。只核查与本 thread 有关的内容，不扩展成整个仓库或其它会话的审计。
- 按实际约定判断完成：代码修改、测试、提交、推送、PR/MR、合并、发布、部署和运行效果各有边界。只要求创建 PR 时，未合并不算遗留；已要求部署验收时，创建 PR 不算完成。
- 用户已明确取消的事项不算遗留；暂缓、受阻或等待用户回复的事项仍算遗留，除非用户已明确将其移出本 thread 或交接到其它位置。交接应说明去向，不能自行把未完成事项视为已转交。
- 结论依赖当前文件、CI、PR/MR 或后台任务状态时，使用可用工具做必要的只读核实。上下文压缩或缺失时，按需读取当前 thread 可用的历史；无法取得关键上下文或证据时，明确缺口，不把“没看到遗留”当成“没有遗留”。

## 报告

先给结论，按需要补充最少的信息：

- **可以关闭**：约定事项均已完成、取消或明确移交，且没有尚需本 thread 跟进的事项。简述依据；有移交时指出去向。
- **仍有遗留，建议保留**：列出具体事项、当前状态和下一步，区分 Agent 可继续处理与需要用户决定或外部结果的事项。
- **暂无法确认，建议保留**：说明缺少什么信息、为何影响判断，以及如何补充核实。

检查请求本身不授权执行遗留事项或关闭操作；若用户同时明确要求处理，按其授权范围执行。
