# CLI 设计偏好

这些偏好用于设计用户直接操作的命令行界面，覆盖命名、输入、输出、交互和配置入口。沿用目标项目已有的对外契约；用户当前明确要求优先。这里不规定测试方式、工具链或发布流程。

## 命名与输入手感

高频 CLI 同时优化记忆成本、按键成本和误操作成本，以常用键盘上的实际输入体验判断取舍。

- 按使用频率分配输入成本。每天反复输入的主命令和主要操作值得优化手感；偶尔执行的安装、初始化和配置操作优先清晰易懂，不强行缩写。
- 名字尽量简短、容易拼写和记忆，优先小写，减少不必要的连字符、大小写切换和组合键。缩写应有可解释的来源，不设统一字符数限制，也不为了少一个字符引入难记的名字。
- 评估连续按键的实际动作：左右手交替、同手不同手指的连续动作、同一手指的跳跃距离、跨行伸展，以及是否需要移动整个手掌。按照实际指法判断，不假设所有人使用标准指法。
- 左右交替和同手相近区域都可作为筛选线索，不规定哪一种一定更好。相邻键不一定由不同手指输入；键位距离也不能单独代表输入成本。
- 将少量候选放进完整常用流程试用，包括命令名后的空格、参数、Tab、Enter，以及输错后的修改。观察是否自然、容易记住和容易打错，不用复杂键位评分替代真实体验。
- 优先减少整个任务的操作次数：让主要用途有直接入口，减少重复参数、无意义层级和多余确认；补全和合理默认值也属于输入手感设计。
- 手感不覆盖语义和命名空间。检查常见工具冲突，以及名字是否容易被误认成另一类工具；不要为了顺手重用含义不同的惯用选项。

上述原则结合 CLI 作者经验与输入研究，但不是人体工学定律。打字速度、准确性和主观舒适度分别评估；不要把速度研究解释为健康收益或某个名字对所有人更舒适。

## 参数与补全

- 单一用途工具优先让主要输入直接成为位置参数，不要求用户每次输入重复的动作名。多用途工具按清晰的资源和动作组织子命令，不为分层而增加层级。
- 辅助操作不能与主要输入争夺同一位置。首个位置参数可接受任意文件名时，安装补全等操作可使用明确选项，避免把普通文件名误判为子命令。
- 常用选项可提供短形式，长形式保持容易理解。沿用目标生态中的惯例，避免大量同义别名增加记忆和维护负担。
- 补全围绕当前位置的实际任务提供候选。路径输入默认优先文件和目录，避免混入帮助、版本等无关选项；仅当用户明确输入选项前缀时再提供适用选项。
- 过滤没有选择价值的候选，例如单独的 `.`；保留用户明确需要的隐藏项、父目录和绝对路径入口。补全负责正确处理空格等 shell 转义，让选择后的参数可直接执行。
- 对需要选择的输入，可以用无参数交互入口降低记忆成本；已经给出明确输入时直接执行，不再要求重复选择。

## 输出与反馈

- 对复制、设置等短暂且重复执行的操作，成功默认静默。需要查看结果时提供显式输出方式；会返回内容的查询命令正常输出结果，不机械套用静默原则。
- stdout 承载结果数据，stderr 承载诊断、进度和失败提示，避免解释性文字污染可供管道使用的结果。
- 错误和降级不能被静默吞掉。说明发生了什么，以及用户可采取的下一步；有可用结果时按约定输出，并明确它与原目标的差别。
- 准确表达可确认的状态。向外部系统发出请求但无法确认结果时，只说明已发送或已尝试，不宣称最终操作成功。
- 输出以用户完成任务所需的信息为限。短操作不增加重复成功提示；长操作及时提供有意义的反馈，避免用户误以为卡住。
- 路径、URL、命令等大概率要复制的内容独占一行，前后不要添加说明、句号、引号或列表前缀；说明放在相邻行。保留内容本身必需的字符和命令所需的引号，不修改数据来追求视觉整齐。

例如，补全安装结果可采用以下布局，实际输出具体路径：

```text
Installed completion in:
/home/user/.local/share/bash-completion/completions/example.bash

Make sure the command is on PATH.
```

独占一行便于选取和复制，但不保证所有终端都能通过双击选中整条路径。

## 配置与初始化入口

- 补全和其它持久化配置由用户显式安装，不在普通调用时自动改动环境。
- 优先使用 shell 或工具约定的独立文件和目录；避免默认直接修改用户的启动文件。确需用户接入时，给出准确、简短的下一步。
- 安装操作可重复执行，保护非本工具管理的现有文件。缺少必要前提时给出可操作的错误，不留下表面成功但不能使用的配置。
- 一次性的开发环境初始化可命名为 `setup`，具体作用通过帮助或描述说明；不要用只覆盖当前某一步的名字限制后续合理扩展。

## 参考依据

- [Command Line Interface Guidelines](https://clig.dev/#naming)：CLI 作者的实践总结，建议名字容易记忆、容易输入，并考虑命名冲突；其 `plum` 改为 `fig` 的案例体现了实际输入动作对命名的影响。[整体指南](https://clig.dev/)也讨论一致性、输出与交互。
- [Microsoft CLI 设计指南](https://learn.microsoft.com/en-us/dotnet/standard/commandline/design-guidance#naming)：建议短且易拼写的名字、小写命名，并控制短选项别名。其特定选项约定属于 .NET 生态，不当作所有 CLI 的统一标准。
- [Observations on Typing from 136 Million Keystrokes，CHI 2018](https://userinterfaces.aalto.fi/136Mkeystrokes/resources/chi-18-analysis.pdf)：部分打字群体的交替双手组合更快，但较慢群体出现相反结果；同手不同手指也可能有类似收益。支持将手部交替作为参考，而非硬性规则。
- [How We Type: Movement Strategies and Performance in Everyday Typing，CHI 2016](https://userinterfaces.aalto.fi/how-we-type/resources/HowWeType_CHI16.pdf)：稳定的手指分工、提前准备下一个按键和较少的整体手部移动与输入表现相关。研究讨论输入表现，不直接证明命令名的舒适度或健康收益。

成功静默、可复制内容独占一行、补全候选范围和显式安装等具体取舍是个人设计偏好，不宣称为所有工具都必须采用的行业标准。
