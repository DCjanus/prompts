# 交付与恢复

按风险和生命周期选择足够的交接信息。简单检索或评审只需结论、证据和局限；长期或独立变更任务才需持续记录 ID、工作区、版本和依赖。不为每个 subagent 建 PR、长文档或完整账本。

## 派工与接手

给接收方足够信息独立执行并验收，通常包括：

- 目标、范围、禁止范围、验收条件、交付对象与位置。
- 必要原始证据入口、已有决策、接口契约，以及仍待核实的判断。
- 实际执行目录、已有改动归属；涉及代码版本时给真实 base/ref/SHA。
- 直接依赖及可消费条件、写入归属、共享资源与约定的使用边界。
- 适用的创建、双向通信、模型、文件修改、提交、发布、合入和历史改写权限，以及原始人类授权来源。

长任务额外保留主/工作会话真实 ID、载体、必要 host、所选模型、上下文来源及 fork 截点、worktree/branch、最后 cursor、待处理通知和下一检查点。账本放在当前会话或已有任务记录即可；需跨会话可读文件时先确认可见性，不假定共享磁盘。

CLI 消息短时按 [会话工具](thread-tools.md) 使用精简简报或双方可读文件；不能靠多条消息反复启动 worker，也不能只传结论却不给证据入口。

## 交付形态与消费条件

| 方式 | 何时使用 | 最低交付内容 |
| --- | --- | --- |
| 结果或评审报告 | 调查、实验、验证或独立评审 | 结论、证据、局限、必要的复现条件或下一步 |
| 工作区修改 | 只授权本地修改或暂不提交 | 真实路径、diff、已有改动边界、验证与未提交状态 |
| 本地提交，组合发布 | 已授权提交和本地集成，希望减少零碎平台审查 | branch/ref、base/head SHA、增量范围与验证 |
| 独立 PR/MR | 人类或项目要求，或适合单独审查的变更 | 真实 URL、最终 head、状态与验证；按能力附加工件 |

未授权 commit 时不能为了提供 SHA 而提交；没有实际 SHA 时明确工作区状态。工具不支持附件时保留 URL 与限制，不假造成功。

依赖允许消费已验收提交时，固定来源 SHA、契约与缺口后即可开工，不必等未要求创建的 PR 或正式合入。项目要求主线前置时等待实际合入，不能用已批准或 CI 通过代替。前置变化先核实新消费条件，再调整受影响任务。

## 验收与集成

主 thread 核实实际结果、diff、适用的 ref/head/base 与验证，不仅复述 worker 自评。独立 reviewer 需要原始需求、当前差异与相关证据，避免被实现者结论锚定；报告说明可复现问题与影响。

验证绑定实际版本和必要环境。head、base 或环境变化时判断哪些证据失效，补相关检查；没有新证据时不重复昂贵测试。queued CI、idle 和“代码完成”均不证明验收或合入条件满足。

指定明确集成人，串行更新集成 ref；必要时用独立集成 worktree，记录来源与新目标 SHA。既检查单项交付，也检查组合后的接口、共享状态和原始需求关键路径。没有文本冲突不代表没有行为冲突。

发布时回读真实 URL、head 与状态；正式合入遵守相应授权与仓库当前门禁。merge queue 入队不等于合入。本地集成、已发布和正式合入分别报告，不提前合入已知损坏版本。

## 基线同步

实际集成或合入后，在已有通信权限内通知受影响 worker：来源 head、集成方式、目标 ref、旧/新目标 SHA、已覆盖前置、影响与需要的验证。只对有依赖变化的任务安排更新，不打断无关工作。

worker 在安全检查点保留未提交工作，按已有历史改写授权同步自己的分支。rebase 前检查祖先与自身提交边界：前置经 squash 或 cherry-pick 集成后，不重放已被覆盖的前置。边界明确时可用 `git rebase --no-update-refs --onto <新目标SHA> <旧前置SHA> <自身分支>` 只重放自身增量；有 merge 提交时另核实拓扑。

冲突先保留现场，核对任务目标和契约后处理，不机械选 ours/theirs 或跳过提交。同步后回报真实 base/head、增量范围与验证。force push 需相应授权，并用明确旧远端 SHA 的 lease；本地同步不自动授权远端写入。

## 阻塞、转交与恢复

报告具体阻塞条件、已完成内容、现场与剩余工作。容量、审批、配额、权限或资源不可用时处理其它就绪工作；不重复创建、绕过限制或让两个 Agent 同时接手同一范围。

转交前确认原执行者安全停点、未提交改动与资源状态，再交给新执行者。接手时核实仓库、分支、任务与当前版本；不只凭旧摘要恢复写入，不将前任验证套到变化后的版本。

独立 thread 用真实 ID、必要 host 与 cursor 恢复等待和读取；queued `clientThreadId` 先确认就绪。subagent 仅在工具支持时恢复或跟进，不能将其 ID 当独立 thread ID。创建结果不确定时先查状态，避免重复任务。

subagent 用原生结果回传。独立 thread 在消息授权内通知，final 保留交付供读取；发送失败不等于交付消失，也不能声称主动通知成功。临时资源交接另按 [通信与共享资源](communication-and-resources.md) 确认。

## 清理

确认结果已接收、交付可定位、所需 ignored 产物已保留、共享资源已恢复，才结束不再需要的 subagent。不终止其它工作腾位或自动归档用户会话。

普通 worktree 按仓库约定与权限清理；管理型 worktree 优先用实际提供的归档工具保存快照。缺少归档能力时保留 checkout 并交付路径与状态，不自行删除。保留用户已有改动与其它 worker 的交付。
